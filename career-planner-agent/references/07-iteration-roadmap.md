# 07 迭代路線圖與增補規範

本 skill 刻意設計成**分代累積**：第一代只掛一個知識底座（古典），把流程與模板
先跑順；之後每一代增加一個獨立的理論來源或語料層，**不推翻前代，只做疊加與標註**。

## 增補語料的規範（每次擴充都要遵守）

1. **標明來源與性質**：新增段落須註明是「哪一本書／哪一套理論的概念架構」，
   以及「Claude 的獨立整理」還是「使用者提供的筆記」。**不收錄原文長段落。**
2. **一個檔案一個來源**：不同流派不要混寫進同一檔，避免概念糊在一起。
   跨流派的比較另開對照表檔案。
3. **衝突要保留**：不同理論對同一問題結論不同時（例如「先找興趣」vs
   「先投入再長出興趣」），**並列呈現並說明各自成立的條件**，不要強行調和。
4. **時效性內容要標日期**：薪資、法規、證照制度、產業趨勢一律加註
   「資料時點：YYYY-MM，使用前請查證」。
5. **更新 SKILL.md 的三處**：版本表、工具箱索引、If-Then 路由表。
6. **記錄在下方版本紀錄**。

## 使用者校正機制

使用者讀完原書或上完課後，可以把自己的理解交給 Claude，用來：
- 修正本 skill 對某個概念的詮釋偏差；
- 補上本 skill 沒有的操作細節；
- **標記反例**：實務上這個框架失效的情況（這類紀錄的價值最高，請優先收）。

修正時在對應檔案末尾以 `> 【使用者校正 YYYY-MM-DD】` 開頭附註，保留原文對照，
不要直接覆蓋，以便看出框架的演化過程。
